# Яндекс Метрика и электронная коммерция KOMUI

## Конфигурация

- Счётчик: `110916310`.
- Контейнер электронной коммерции: `dataLayer`.
- Валюта: `RUB`.
- Webvisor, карта кликов, точный показатель отказов и отслеживание ссылок включены.
- Отправка данных через JavaScript включена только на `komui.ru` и `www.komui.ru`. `stage.komui.ru`, localhost и локальные HTML-файлы не отправляют тестовые визиты в продовый счётчик.
- HTML-редиректы со старых URL товаров намеренно не считаются отдельными страницами: пользователь сразу переходит на каноническую карточку, где просмотр будет зарегистрирован.

Счётчик и общий модуль аналитики добавляются генератором на главную, служебные страницы, все канонические карточки товаров и страницы коллекций. Источники реализации:

- `assets/metrika.js` — единый API целей и e-commerce, фильтрация персональных данных, защита покупки от дублей;
- `index.html` — каталог, быстрый просмотр и корзина;
- `checkout.html` — оформление, СДЭК, промокод и переход в Т-Банк;
- `payment-result.html` — подтверждённая оплата;
- `scripts/build-products.js` — подключение счётчика и разметка сгенерированных страниц товаров/коллекций.

## Цели, которые нужно создать в интерфейсе Метрики

Тип каждой цели: **JavaScript-событие**. Поле «Идентификатор цели» нужно заполнить в точности значением из таблицы.

### Основные цели

| Идентификатор | Название в Метрике | Когда срабатывает | Рекомендация |
|---|---|---|---|
| `order_paid` | Заказ оплачен | Бэкенд подтвердил статус `paid` | Сделать главной целью |
| `begin_checkout` | Начато оформление | Покупатель перешёл из корзины в checkout | Основная воронка |
| `add_to_cart` | Товар добавлен в корзину | Быстрое добавление, карточка или увеличение количества | Основная воронка |
| `product_view` | Просмотр товара | Открыта карточка товара или быстрый просмотр | Основная воронка |
| `checkout_submit` | Отправлена форма заказа | Поля и пункт СДЭК прошли проверку, начинается создание платежа | Основная воронка |
| `payment_redirect` | Переход к оплате Т-Банк | Платёж создан и браузер перенаправляется в Т-Банк | Основная воронка |
| `cdek_point_selected` | Выбран пункт СДЭК | Получен успешный расчёт доставки для выбранного ПВЗ | Основная воронка |
| `promo_applied` | Промокод применён | Бэкенд подтвердил действующий промокод | Основная воронка |

### Диагностические цели

| Идентификатор | Название в Метрике | Когда срабатывает |
|---|---|---|
| `catalog_view` | Просмотр каталога | Загружена главная или страница коллекции с товарами |
| `cart_open` | Открыта корзина | Открыта панель корзины |
| `remove_from_cart` | Удаление из корзины | Уменьшено количество или удалена позиция |
| `cdek_picker_open` | Открыт выбор ПВЗ | Открыто окно карты/списка СДЭК |
| `promo_copied` | Промокод скопирован | Нажата кнопка копирования в промо-плашке |
| `payment_create_failed` | Ошибка создания платежа | API не создал платёж или не вернул URL оплаты |
| `payment_failed` | Оплата не прошла | Бэкенд вернул `payment_failed`, `canceled` или `refunded` |
| `payment_review` | Платёж требует проверки | Бэкенд вернул `payment_review` из-за расхождения данных |

Не нужно создавать отдельные JavaScript-цели для `impressions`, `click`, `detail`, `add`, `remove`, `purchase`, `promoView` и `promoClick`: это действия электронной коммерции, они передаются через `dataLayer` и используются в e-commerce-отчётах. При необходимости их можно дополнительно использовать в сегментах Метрики.

## Какие e-commerce-события передаются

| Действие | Место | Содержимое |
|---|---|---|
| `impressions` | Главный каталог и страницы коллекций | ID, название, цена, категория, коллекция, позиция и список |
| `click` | Клик по карточке/ссылке товара | Товар и список, из которого был выполнен переход |
| `detail` | Карточка товара или быстрый просмотр | Товар, цена, категория и коллекция |
| `add` | Добавление товара или увеличение количества | Товар, размер, количество и источник |
| `remove` | Уменьшение количества или удаление позиции | Товар, размер и удалённое количество |
| `purchase` | Только подтверждённый сервером статус `paid` | Номер заказа, выручка, промокод и состав заказа |
| `promoView` | Показ верхней промо-плашки | Промо `KOMUI10` и позиция размещения |
| `promoClick` | Копирование промокода | Промо `KOMUI10` и позиция размещения |

`purchase` защищён от повторной отправки ключом номера заказа в `localStorage`. Обновление страницы результата оплаты или повторный опрос статуса не создаёт второй заказ в Метрике.

## Данные и приватность

В Метрику не передаются email, телефон, ФИО, адрес клиента, токены оплаты или токены доступа. Передаются только технические параметры воронки, номер заказа, код ПВЗ/тарифа, сумма, промокод и обезличенные данные товаров.

## Проверка после деплоя

1. Открыть `https://komui.ru/?_ym_debug=2&metrika_debug=1` и DevTools → Console. `_ym_debug=2` включает штатную диагностику Метрики, а `metrika_debug=1` — дополнительный внутренний журнал KOMUI с префиксом `[KOMUI analytics]`.
2. В Network проверить загрузку `mc.yandex.ru/metrika/tag.js?id=110916310` и запросы к `mc.yandex.ru/watch/110916310`.
3. Пройти воронку: товар → корзина → checkout → ПВЗ СДЭК → тестовая оплата.
4. В Метрике открыть «Отчёты → Стандартные отчёты → Содержание → Электронная коммерция» и убедиться, что появились просмотры товаров, добавления и покупка.
5. Проверить цели в отчёте «Конверсии». Новые цели могут появляться в отчётах с задержкой.
6. На `stage.komui.ru` убедиться, что тег Метрики не загружается; для локального просмотра сформированных `dataLayer`-событий можно использовать `?metrika_debug=1`.

Перед переходом в Т-Банк цель `payment_redirect` ждёт callback Метрики, но не дольше 800 мс. Это снижает риск потери события при выгрузке страницы и одновременно не блокирует оплату при недоступности Метрики. Для денежной цели `order_paid` передаётся штатный параметр Метрики `order_price` в рублях; поле `revenue` остаётся в e-commerce purchase и в технических параметрах цели.

## Правило для будущих доработок

Новые действия магазина нужно отправлять через `window.KomuiAnalytics`. Нельзя вызывать `ym()` напрямую из разных компонентов и нельзя добавлять в параметры цели контактные или платёжные данные пользователя. Новые товары автоматически попадут в существующую e-commerce-разметку после обычной генерации страниц.
