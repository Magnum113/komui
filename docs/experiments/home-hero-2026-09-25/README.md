## Как включить в Varioqub

1. Сначала выложить код и шесть WebP на сайт, затем убедиться, что главная **без эксперимента** выглядит как A. Проверить загрузку `https://abt.s3.yandex.net/expjs/latest/exp.js` и ответы Varioqub. Код работает только на `komui.ru` и `www.komui.ru`; локальные и staging-адреса Varioqub не вызывают.
2. В счётчике Метрики `110916310` создать эксперимент типа **«Флаги в коде»** только для главной. Контроль A — без флага; B/C/D — ключ `komui_home_hero` со значением `B`, `C` или `D` соответственно. Система берёт последнее значение массива флага, неизвестные значения игнорирует. Не добавлять флаг в другие эксперименты одновременно.
3. До запуска проверить превью всех четырёх веток на десктопе и телефоне, кликабельность «Смотреть каталог», отсутствие горизонтальной прокрутки и реальные загрузки WebP. Основная метрика — оплаченный заказ / ecommerce purchase, вспомогательная — переход в каталог. Сравнивать конверсии на одинаковом периоде и отдельно по устройствам, не делать вывод по одним кликам.

На сайте при отсутствии ответа Varioqub или ошибке загрузки `exp.js` остаётся A. B/C/D не включаются параметром URL или локальным хранилищем посетителя. Вариант устанавливается только по ответу Varioqub.

## Прямые ссылки на staging

Staging защищён существующим Basic Auth. Эти ссылки отображают те же HTML, CSS и WebP, что получает соответствующий вариант на проде, но не запускают Varioqub и не записывают тестовые визиты в продовую Метрику:

| Вариант | Ссылка |
| --- | --- |
| A | https://stage.komui.ru/?komui_home_hero=A |
| B | https://stage.komui.ru/?komui_home_hero=B |
| C | https://stage.komui.ru/?komui_home_hero=C |
| D | https://stage.komui.ru/?komui_home_hero=D |

Параметр работает только на главной staging; на `komui.ru` и `www.komui.ru` URL не переключает вариант. Чтобы превью оставались синхронными с публичным тестом после будущих правок, выкладывать один и тот же проверенный Git commit сначала на staging, затем на prod и сверять версии релизов.

Из-за клиентского получения флага может быть краткое мерцание A перед B/C/D. [Антифликер Яндекса](https://yandex.ru/support/varioqub/ru/anti-flicker) пока не включён: стандартный пример скрывает всю страницу до 4 секунд, даже когда тест ещё не идёт. Перед запуском следует проверить фактическое мерцание на мобильной сети и при необходимости включить ограниченное скрытие только hero с коротким таймаутом. Это отдельная UX-проверка, а не условие подключения Varioqub.

Для воспроизводимой локальной проверки можно установить атрибут `data-komui-hero-variant="B"`, `"C"` или `"D"` у элемента `<html>` в DevTools; удалить атрибут для A. Это не включает эксперимент у других посетителей.

Источники: [подключение Varioqub](https://yandex.ru/support/varioqub/ru/connect), [флаги в коде](https://yandex.ru/support/varioqub/ru/create/types/flags), [ответ `init`](https://yandex.ru/support/varioqub/ru/objects/init).
