## Рабочая конфигурация Varioqub

- Тип — «Флаги в коде», распределение равное: A/B/C/D по 25% от 100% аудитории. Страницы проведения — только `komui.ru/`; поисковые роботы исключены. Период оставлен как задано в интерфейсе: **25 сентября — 30 октября 2026 года**.
- Метрики оставлены как выбраны при создании: основная — конверсия в цель «Товар добавлен в корзину», дополнительная — конверсия в цель «Просмотр товара». Оплаченные заказы оценивать отдельно как бизнес-результат: они не являются основной метрикой этого эксперимента.
- A — без флага; B/C/D — один ключ `komui_home_hero` со значениями `B`, `C`, `D` соответственно. Код берёт последнее значение массива флага и игнорирует неизвестные значения. Не добавлять этот ключ в другой эксперимент одновременно.
- Код и шесть WebP выложены на staging и prod из одного коммита `e63683a7defb`. После запуска продовый браузер реально получил D и отобразил соответствующий hero. [Отчёт Varioqub](https://metrika.yandex.ru/ab/result/75857/?id=110916310).
- После запуска эксперимента исправлено только мобильное кадрирование B/C/D, без смены флагов и распределения. Для загрузки нового CSS у посетителей его URL дополнен `?v=20260925-crop2`. При анализе результатов учитывать эту дату изменения: показы до и после исправления не являются полностью одинаковыми креативами.

На сайте при отсутствии ответа Varioqub или ошибке загрузки `exp.js` остаётся A. B/C/D не включаются параметром URL или локальным хранилищем посетителя. Вариант устанавливается только по ответу Varioqub.

## Прямые ссылки на staging

Staging защищён существующим Basic Auth. Эти ссылки отображают те же HTML, CSS и WebP, что получает соответствующий вариант на проде, но не запускают Varioqub и не записывают тестовые визиты в продовую Метрику:

| Вариант | Ссылка |
| --- | --- |
| A | https://stage.komui.ru/?komui_home_hero=A |
| B | https://stage.komui.ru/?komui_home_hero=B |
| C | https://stage.komui.ru/?komui_home_hero=C |
| D | https://stage.komui.ru/?komui_home_hero=D |

Параметр работает только на главной staging; на `komui.ru` и `www.komui.ru` URL не переключает вариант. Чтобы превью оставались синхронными с публичным тестом после будущих правок, выкладывать один и тот же проверенный Git commit сначала на staging, затем на prod и сверять версии релизов.

Из-за клиентского получения флага может быть краткое мерцание A перед B/C/D. [Антифликер Яндекса](https://yandex.ru/support/varioqub/ru/anti-flicker) не включён: стандартный пример скрывает всю страницу до 4 секунд. Во время теста стоит проверить фактическое мерцание на мобильной сети; если оно заметно, отдельно оценить короткое скрытие только hero.

Для воспроизводимой локальной проверки можно установить атрибут `data-komui-hero-variant="B"`, `"C"` или `"D"` у элемента `<html>` в DevTools; удалить атрибут для A. Это не включает эксперимент у других посетителей.

Источники: [подключение Varioqub](https://yandex.ru/support/varioqub/ru/connect), [флаги в коде](https://yandex.ru/support/varioqub/ru/create/types/flags), [ответ `init`](https://yandex.ru/support/varioqub/ru/objects/init).
